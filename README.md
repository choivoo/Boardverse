# Boardverse 1.0 RC

체스·오목 보드게임 플랫폼. **하나의 Node 서버**가 웹앱(React + TypeScript + Vite, PWA), REST API, WebSocket 대국 서버, SQLite DB를 모두 제공합니다. **아직 어디에도 배포되지 않았습니다.**

## 실행
```
npm install
npm run serve            # 빌드 후 서버 실행 → http://localhost:8787
npm run dev              # 클라이언트 개발 서버(5173, /ws는 8787로 프록시) — 다른 터미널에서 npm start 필요
npm test                 # vitest 62개 (규칙·스토어·마이그레이션·HTTP+WebSocket 통합·퍼즐)
npm run build            # tsc 타입 검사 + vite 빌드
scripts/dev-server.sh    # E2E용 일회용 서버(:8787, 메모리 DB, 관리자 boss@example.com) → node scripts/e2e.mjs (Chromium 필요)
```
Node 22.5+ (내장 `node:sqlite` 사용 — 실험적 기능 경고가 출력될 수 있음).

## 환경변수 (`.env.example` 참고)
| 이름 | 설명 |
|---|---|
| `PORT`, `DATABASE_PATH` | 포트, SQLite 파일(기본 `./data/boardverse.db`, Docker는 `/data/boardverse.db`) |
| `NODE_ENV=production` | 개발용 메일 outbox 비활성. **SMTP가 없으면 이메일 기능(인증·재설정)은 꺼지고 UI에 그렇게 표시됨** |
| `SMTP_URL`, `MAIL_FROM`, `PUBLIC_URL` | 실제 메일 발송. `SMTP_URL`이 있으면 `PUBLIC_URL`(메일 링크용 절대 주소) 필수 — 없으면 서버가 시작을 거부 |
| `ADMIN_EMAILS` | 관리자 이메일(쉼표 구분). **관리자 = 목록에 있고 + 이메일이 인증된 계정.** SMTP가 없으면 운영자가 `DATABASE_PATH=… npx tsx scripts/verify-user.ts you@example.com`으로 직접 인증 처리 |
| `COOKIE_SECURE=1` | Secure 쿠키·HSTS 강제(기본은 `X-Forwarded-Proto: https`일 때 자동) |

기본 관리자 계정이나 하드코딩된 비밀은 없습니다.

## Docker (이 환경에서 검증함)
```
docker build -t boardverse .
docker run -d -p 8787:8787 -v bv-data:/data -e NODE_ENV=production -e ADMIN_EMAILS=you@example.com boardverse
```
- **`/data` 볼륨 필수** — 없으면 컨테이너 교체 시 계정·레이팅·기록이 사라집니다.
- 헬스 체크: `GET /healthz` (DB 조회 포함). `SIGTERM` 시 WebSocket·HTTP·DB를 닫고 종료합니다.
- **인스턴스 1개만** 운영하세요(대국 방이 서버 메모리에 있음). 서버를 재시작하면 *진행 중인 대국은 사라지고 기록·레이팅에 반영되지 않습니다*(끝난 대국·계정·시즌·대회·클럽은 DB에 보존).
- HTTPS(리버스 프록시에서 종료, `X-Forwarded-Proto` 전달, WebSocket 업그레이드 허용)가 필요합니다. PWA 설치·서비스워커·Secure 쿠키가 HTTPS를 요구합니다.
- DB 스키마는 `PRAGMA user_version` 기반 마이그레이션(`server/migrate.ts`)으로 기존 DB를 제자리에서 올립니다(v1→v2 테스트 포함). 기존 체스 레이팅은 새 분류로 복사하지 않고 동결된 "기존(legacy)"으로 보존됩니다.

## 기능 (구현·검증된 것만)
- **대국**: 체스(chess.js: 캐슬링·앙파상·승격·체크메이트/스테일메이트·3회 반복·50수·기물 부족, 시계 1/3/5/10분·15+10·무제한), 오목(자체 엔진, 13/15/19, 프리스타일 5목 이상·금수 없음). 컴퓨터 대국(약한 휴리스틱, 브라우저에서 오프라인 실행, 힌트·되돌리기), 같은 기기 2인.
- **온라인**: 방 코드/링크, 빠른 매칭, 서버가 좌석·차례·합법 수·서버 시계·승패 판정, 중복/오래된 요청 무시, 재접속, 120초 끊김 몰수패, 무승부 제안, 재대결, 친구 초대.
- **계정**: 이메일 가입/로그인(scrypt, HttpOnly 쿠키, 시도 제한, 출처 검사), 이메일 인증, 비밀번호 재설정(일회용·1시간 만료·해시만 저장·계정 존재 비노출·재설정 시 모든 세션 폐기), 비밀번호 변경, 데이터 내보내기, 계정 삭제.
- **레이팅**: 평가 대국(로그인한 두 사람)만 Elo(시작 1200, 20판 미만 K=40, 이후 20). **게임·시간 분류별 분리**: 체스 = 불릿(추정 시간 < 180초)·블리츠(< 480초)·래피드·무제한, 오목 = 기본. 추정 시간 = 기본 초 + 40×증가 초(`src/ratingConfig.ts` 한 곳에서 정의). 봇·게스트·친선·대회·2수 미만 대국은 제외, 같은 대국 중복 반영 없음. 분류별 랭킹(페이지네이션·내 순위).
- **시즌**: 데이터 정의(`src/seasons.ts`, UTC), 서버 집계, 보상 1회 수령, 종료 후 분류별 TOP 10 스냅샷(서버 tick이 자동 실행).
- **상점**: 보드 테마·체스 말·오목 돌·프로필 테두리(코스메틱 전용). 코인은 사람과의 대국(6수 이상)에서 서버가 지급(일 100 상한). 현금 결제·뽑기 없음.
- **대회(아레나)**: 관리자가 생성(게임·시간·시작/종료), 참가/취소, 대회 시간 동안 참가자끼리 큐로 경기 매칭(서버가 대회 설정을 강제), 승 2·무 1·패 0, 실시간 순위·종료 시 최종 순위 확정(멱등). 레이팅에는 영향 없음.
- **클럽**: 생성·검색·가입(공개 즉시 / 승인제 요청)·초대·수락·탈퇴·내보내기, 소유자/관리자/멤버 권한(서버 검증), 소개·공지, 차단 규칙 적용, 클럽 신고. *클럽전은 미지원.*
- **관전**: 읽기 전용(수·기권·무승부·채팅 모두 서버가 거부), 공개 목록은 "관전 허용" 빠른 매칭/대회 대국만. 친구 방은 기본 비공개, **평가 대국은 관전 불가**, 최대 20명.
- **채팅**: 대국 중 두 플레이어 사이만(로그인 필수), 200자·링크 금지·1초 간격·10초당 5개, 상대 채팅 숨기기, 신고 시 서버가 직접 보관한 최근 대화를 증거로 첨부(메모리 보관, 신고에만 저장).
- **신고·관리자**: 사용자/클럽 신고(토큰·비밀번호 패턴 가림, 하루 10건), 관리자 화면(상태 접수/검토 중/조치 완료/기각, 메모), **모든 열람·처리가 감사 로그에 기록**. 권한은 서버가 매 요청 검증.
- **학습**: 직접 생성·검증한 퍼즐(체스 12·오목 16), 오늘의 문제, 복기 뷰어, 체스 PGN 내보내기/불러오기(검증). 단순 기보 뷰어이며 **엔진 평가가 아님**.
- **모바일/폴더블 UI**: 하단 탭, 커버(~360px)·펼침(~780×700, 600×900) 레이아웃, 터치 오목 "탭→확정", PWA(오프라인 로컬 플레이; 서비스워커는 `/api`·`/ws`를 캐시하지 않음).

## 정책 요약
- 연결 끊김: 120초 내 같은 기기에서 재접속하면 이어서 진행, 넘으면 상대 승. 시간 초과·기권·몰수 모두 서버가 판정.
- 게스트끼리의 대국은 서버에 저장하지 않음. 코인 농사 방지(사람과 6수 이상, 일 상한). 두 계정이 짜고 레이팅을 올리는 담합은 막지 못함(신고·관리자 처리만 가능).
- 채팅 로그는 파일/DB에 상시 저장하지 않음(방 메모리 최대 50줄, 신고 시에만 20줄 첨부).

## 알려진 제한 (미구현·미검증)
- **미배포.** 공개 서비스가 아닙니다. 실제 SMTP로 메일을 보내본 적 없음(전송 계층은 가짜 transport 단위 테스트까지; 개발 모드는 서버 메모리 outbox).
- **엔진 분석·오프닝 탐색기 없음**: 이 환경에 Stockfish가 없고(바이너리·패키지 미설치), 오프닝 데이터 출처도 확보하지 못했습니다. 연결하려면 라이선스(Stockfish는 GPL-3.0)를 검토하고 서버/워커 분리, 분석 시간 제한, 평가 대국 중 사용 차단을 구현해야 합니다. 봇은 약한 휴리스틱이며 힌트도 같은 봇이 제안합니다.
- 클럽전·Chess960·렌주 금수·운영자용 사용자 제재(정지) 기능 없음(신고 처리 기록만). 이메일 변경 기능 없음.
- 대국 방은 메모리 → 서버 재시작 시 진행 중 대국 소실, 다중 인스턴스 불가. 관전 지연 없음(그래서 평가 대국은 관전 금지).
- 대회: 같은 두 사람이 연속으로 다시 매칭될 수 있음(회피 로직 없음).
- 실제 갤럭시 Z 폴드 기기 테스트 없음(Chromium 모바일 에뮬레이션만, 반접힘 자세 미검증). ESLint 미설정.
- 이미지: `codex` CLI/이미지 생성 도구가 없어 모든 자산(워드마크·카드 일러스트·기물 6종·PWA 아이콘)을 직접 SVG로 제작.
- 퍼즐 진행·최근 기록은 브라우저에만 저장(서버 동기화 없음).
